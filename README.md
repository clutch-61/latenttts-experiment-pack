# 在潜空间里做推理：基线系统与我们的训练方法

这个仓库给**没跟过实验的人**看：问题是什么、两个系统分别做什么、数字怎么读。代码路径写在后文，正文尽量不用内部缩写。

本仓库只包含两套可复现系统：

1. **基线**：原论文式的潜空间推理模型 + 用交叉熵训练的潜空间奖励模型，再做 Best-of-N。
2. **我们的方法**：在上述生成器上继续训练，用更强的奖励模型筛选轨迹，并加一项很轻的分布对齐损失；测试时用该奖励模型挑样本。

不包含中间失败过的其它配方。本仓库也不放模型权重和训练数据，需要自行准备。

---

## 1. 先讲背景（不需要读过我们实验笔记）

常见大模型做数学题时，会先写出一步步文字推理（chain-of-thought），再给出答案。

**COCONUT**（Hao 等人）换了一种做法：推理不一定要写成自然语言，而是在模型内部用若干连续向量（latent token，潜变量步）来「想」，再解码出最终答案。好处是推理不必挤在离散词表里；坏处是人读不到中间过程，也很难用普通文本奖励去打分。

**LatentTTS / LatentRM** 做的是：再训练一个**潜空间奖励模型**。它不看（或不仅看）文字步骤，而是给整段潜变量轨迹打分。测试时生成器对同一道题采样多条轨迹，奖励模型挑分最高的那条，这就是 **Best-of-N**。

本仓库的「基线」就是：

- 生成器：官方/复现的 **COCONUT**，训练阶段冻住，不再改权重。
- 奖励模型：只用「答案对不对」一类监督、用交叉熵训练出来的潜空间打分器（代码目录里常叫 `latentrm_baseline`）。
- 测试：Best-of-N，并按原论文习惯在奖励模型上开 **MC-dropout = 0.2**（用 dropout 当贝叶斯近似，分数带一点不确定性）。

「我们的方法」不换任务、不换评测集，只改生成器怎么继续训练、测试时用哪一个奖励模型、以及测试时是否还开 dropout。

## 2. 评测怎么做（读表前必看）

**数据**（需自行放到 `data/`）

| 集合 | 含义 |
|------|------|
| GSM8K Test | 小学应用题，主表 |
| GSM-Hard | 把数字改大、更难 |
| MultiArith | 较简单的算术应用题 |

**共同设定**

- 随机种子 **42**
- 每题最多生成 **128** 个新 token
- 采样条数 **N ∈ {1, 4, 16, 64}**
- **N = 1** 时：生成器确定性解码，**不用**奖励模型
- **N ≥ 4** 时：生成 N 条候选，用奖励模型排序

**同一批候选上我们会报四种数**（不要把不同列拿去和不同论文对打）

| 列名 | 含义 |
|------|------|
| 选最高分（Best-of-N / top1） | 奖励模型分数最高的那一条，对了算对。**论文口径的主列。** |
| 加权投票 | 把相同答案的分数加起来，投给总分最高的答案 |
| 多数票 | 不管分数，出现次数最多的答案 |
| 覆盖率 | 这 N 条里，至少有一条答案是对的比例。覆盖率高但选最高分低，说明「池子里有对的，但奖励模型没挑中」 |

**两种测试协议，不要混减**

| 协议 | 奖励模型 dropout | 用来干什么 |
|------|------------------|------------|
| 论文口径 | **0.2** | 和原 LatentRM 设定对齐；基线钉死在这一列 |
| 我们方法的选定部署 | **关掉**（不设 dropout） | 方法最终怎么用 |

基线在 GSM8K Test、N=16、论文口径下，选最高分是 **28.43%**。这是分母。不要拿「关掉 dropout 的旧基线约 33.7%」来减我们的方法。

## 4. 我们的方法（在生成器上继续练）

目标不变：同一套数学题、同一套 Best-of-N 评测。改的是生成器，让它更容易产出「奖励模型认为好、答案又对」的潜变量轨迹。

### 还要准备一个更强的奖励模型

基线奖励模型只学「像正确答案的轨迹」。另外我们训练了一个**带步骤顺序偏好**的奖励模型（代码目录 `outputs/latentrm_order_pref`）：它不仅看对错，还希望潜变量轨迹的「先后结构」更合理。  
**训练生成器时这个模型冻住，只当裁判，不更新。**

测试我们方法时，Best-of-N 用的是这个偏好奖励模型，而不是基线交叉熵奖励模型。

### 训练分两段（都从 COCONUT 出发或接着上一段）

**第一段：老师当安全网，学生偶尔才能「用自己的轨迹当训练目标」。**

- 老师：原始 COCONUT，每题贪心解一次。
- 学生：当前生成器，每题采 **64** 条轨迹。
- 只有同时满足下面三条，才用学生自己的轨迹做交叉熵；否则仍模仿老师：
  1. 学生这条轨迹的**最终答案对**；
  2. **偏好奖励模型**给学生的分高于老师；
  3. **基线奖励模型**认为学生没有明显比老师更差（允许 0.5 的松弛），避免只追偏好分、轨迹「不健康」。
- 另外用 **Self-Forcing**：潜变量步用可微的方式滚下去，再对最终答案做交叉熵，避免「训练时看见真轨迹、测试时全靠自己滚」的落差。
- 这一段**没有**下面说的分布对齐项。我们实验里跑 **1500** 步。

**第二段：在上一段检查点上，加很轻的分布对齐。**

仍用同一套「对不对 + 两个奖励模型」门控。再加一项 **MMD**（最大均值差异）：把学生潜变量的一种「内容视角」表示，往「做过对的轨迹」的分布上轻轻拉。系数 **0.05**，前 100 步从 0 慢慢升到 0.05。  
**不**再训偏好奖励模型，也**不加**别的潜空间对齐损失。学习率 `3e-6`，同样 1500 步。超参快照见 [`recipes/p2mmd05_train_args.json`](recipes/p2mmd05_train_args.json)。

脚本：`CKPT=<第一段检查点> bash scripts/train_p2mmd05.sh`  
一体训练代码：`scripts/train_p123_system.py`（`lambda_mmd=0` 是第一段，`=0.05` 是第二段）。

### 选定怎么测我们的方法

偏好奖励模型 + Best-of-N，**关掉 dropout**，种子 42。N=1 仍是生成器自己贪心、不用奖励模型。

脚本：`GEN=<第二段生成器> bash scripts/eval_p2mmd05_none.sh`（默认 GSM8K Test、N=16）。

## 5. 数字（种子 42）

主对比用**论文口径（dropout=0.2）**，两边公平。表里 N≥4 的格子是：

**选最高分 / 加权投票 / 多数票 / 覆盖率**（单位：%）。N=1 只有生成器准确率。

### GSM8K Test

| N | 基线（COCONUT + 交叉熵奖励模型） | 我们的方法（续训生成器 + 偏好奖励模型） |
|---|----------------------------------|------------------------------------------|
| 1 | 34.42 | 35.18 |
| 4 | 29.42 / 30.17 / 29.72 / 40.41 | 32.37 / 33.43 / 33.66 / 44.12 |
| 16 | **28.43** / 29.80 / 31.77 / 52.69 | 34.04 / 35.94 / 35.86 / 56.56 |
| 64 | 27.75 / 29.34 / 31.92 / 63.08 | 31.77 / 33.97 / 35.94 / 66.11 |

GSM8K、N=16、选最高分：基线 **28.43** → 方法 **34.04**，大约 **+5.6 个百分点**。

覆盖率大约一半：很多题的 16 条样本里根本没有正确答案，奖励模型再强也救不回来。N 越大，选最高分有时还会掉，说明打分器会把错的挑上来。

### GSM-Hard

| N | 基线 | 我们的方法 |
|---|------|------------|
| 1 | 7.66 | 7.97 |
| 16 | **5.46** / 5.61 / 6.37 / 12.59 | 7.74 / 7.81 / 8.35 / 13.51 |

覆盖率大约 13%：绝大多数题的候选池是空的（没有对的答案）。难的是生成，不只是挑样本。

### MultiArith

| N | 基线 | 我们的方法 |
|---|------|------------|
| 1 | 80.86 | 85.69 |
| 16 | **71.03** / 76.72 / 75.52 / 92.24 | 83.10 / 84.66 / 84.14 / 93.97 |

### 方法按「关掉 dropout」部署时（不是和基线同一协议）

| 集合 | N | 选最高分 | 加权投票 | 多数票 | 覆盖率 |
|------|---|---------|---------|--------|--------|
| GSM8K Test | 1 | 35.18 | — | — | — |
| GSM8K Test | 16 | 34.80 | 36.77 | 35.94 | 52.84 |
| GSM-Hard | 16 | 8.19 | 8.27 | 8.04 | 12.90 |
| MultiArith | 16 | 85.52 | 87.41 | 86.21 | 92.07 |

关掉 dropout 之后，加权投票略高于「只信最高分」。若要和基线比涨幅，请用上一节 **dropout=0.2** 的表，不要用这一节减 28.43。

## 6. 怎么跑

依赖见 `requirements.txt`。需要自备：GSM 等 json、COCONUT 权重、两个奖励模型检查点、以及第一段训练的生成器检查点。

```bash
# 训练基线潜空间奖励模型（交叉熵）
bash scripts/train_baseline_detach.sh

# 训练带顺序偏好的奖励模型（生成器训练时冻住当裁判）
# python -m src.train_order_pref training_args/train_order_pref.yaml

# 论文口径：冻住的 COCONUT + 基线奖励模型，dropout=0.2
CUDA_VISIBLE_DEVICES=0 bash scripts/eval_paper_b0_baseline.sh

# 第二段：在第一段生成器上加 MMD=0.05 继续训
CKPT=outputs/p123_dualBeat/model bash scripts/train_p2mmd05.sh

# 方法部署评测：新生成器 + 偏好奖励模型，关掉 dropout，GSM N=16
GEN=outputs/p123_p2mmd05/model bash scripts/eval_p2mmd05_none.sh
```
